# Zotero RSS 单篇论文研究工作流

本文件供单篇 `research` subagent 使用。一个 subagent 只处理一篇论文。

## 输入

调用方必须提供：

- DOI。
- 标题。
- 原始 URL。
- PDF 绝对路径。
- Markdown 绝对路径。
- 单篇输出目录绝对路径。
- 预期 `report.md` 绝对路径。
- 报告语言。

PDF 只作为备用证据路径。主要证据来自 MarkItDown 生成的 Markdown。

## 身份校验

正式分析前，先确认目标论文身份。至少满足以下两项一致，才继续研究：

- DOI 与输入 DOI 一致。
- 标题与输入标题一致或高度一致。
- 作者列表或摘要关键词与输入论文一致。

如果无法确认至少两项一致，不生成实质性分析；最终回复失败原因，交由调用方标记失败。

## 证据抽取

不要一次性读取整份 Markdown。先用轻量命令定位结构，再读取有限片段。

1. 统计文件规模并定位章节：

   ```bash
   wc -l "{markdownPath}"
   rg -n "^(#|##|[0-9]+\\.|Abstract|Introduction|Method|Methods|Results|Discussion|Conclusion|References|Funding|Disclosure|Data availability)" "{markdownPath}" | head -160
   ```

2. 优先抽取这些部分，每部分控制在可读范围内：
   - 标题、作者、摘要和 DOI 附近。
   - 引言、研究问题，以及论文类型线索，例如方法论文、经验研究、综述或数据资源论文。
   - 方法、数据、样本、实验设计、分析流程、评价指标和 baseline / 对照。
   - 实验、结果、案例、评估，以及关键表格或图对应的正文说明。
   - 讨论、局限、结论，以及代码、数据或补充材料可得性说明。
3. 如果章节标题识别不稳定，用 `rg` 搜索关键词后再用 `sed -n` 读取附近行。优先搜索：
   - `dataset|data|sample|participants|benchmark`
   - `metric|accuracy|f1|auc|rmse|ablation|baseline`
   - `code availability|data availability|supplementary|limitation`
4. 只在 Markdown 缺失、明显不是目标论文或关键信息无法确认时，才使用 PDF 路径作为备用线索。

## 论文类型分流

- 经验研究：优先记录数据或样本、指标、baseline、关键数值结果和局限。
- 综述或观点论文：优先记录问题框架、分类方式、争议点和研究议程。
- 数据或资源论文：优先记录资源来源、规模、构建流程、标注方式和可用性。
- 如果论文类型不明确，明确写“不确定”，不要强行套入单一类别。

## 报告要求

使用 `references/research-item-report-template.md` 的结构生成报告。

报告必须：

- 使用调用方指定语言。
- 包含 DOI。
- 包含论文类型。
- 区分论文声称、实验结果、作者推测和研究者自己的判断。
- 对每条关键发现使用固定结构：
  - 发现内容
  - 类型：`实验结果` / `作者主张` / `作者解释` / `研究者判断`
  - 证据位置：例如摘要、Methods、Results、Table 2、Figure 3、Discussion 或 Conclusion
  - 关键数值：如适用
  - 置信度：`高` / `中` / `低`
- 对重要结论标明证据来自论文的哪个部分，例如摘要、实验结果、表格、图、讨论或结论。
- 对经验研究尽量保留数据集或样本、主要指标、baseline 或对照，以及至少 1 个关键数值结果；如果当前证据无法可靠提取，明确写“当前证据下无法可靠提取关键数值”。
- 尽量记录代码、数据和补充材料是否公开，以及复现所需关键信息是否充分。
- 不要把单数据集、单场景或单案例结果写成普适结论；对因果解释和外部推广保持谨慎措辞。
- 对无法确认的信息写“不确定”或“论文未说明”。
- 不编造作者、年份、数据集、指标、实验结果或代码公开状态。

如果 Markdown 无法读取、明显不是目标论文，或转换结果不足以支持研究，不生成实质性分析；
最终回复失败原因，交由调用方标记失败。

## 完成门禁

单篇任务的交付物是磁盘上的 `report.md`，不是最终回复文本。

必须按以下顺序完成：

1. 使用写入工具把完整报告写入预期 `report.md` 绝对路径。
2. 验证文件存在且大小大于 0。
3. 验证正文包含该论文 DOI。
4. 验证正文包含论文类型，并至少有 1 条带证据位置的关键发现。
5. 如果论文属于经验研究，验证报告至少满足以下之一：
   - 包含至少 1 个关键指标或数值结果。
   - 明确写出“当前证据下无法可靠提取关键数值”。
6. 验证通过后，最终回复只报告报告路径和验证结果。

简写为：`write -> verify -> final`。

未通过本门禁时，不得声称报告已完成。
