# Zotero RSS 汇总研究工作流

本文件供汇总 `research` subagent 使用。汇总阶段只在所有条目达到终态后启动。

## 输入

调用方必须提供结构化输入，不让 subagent 重新扫描下载目录猜测状态：

- `process-items.json` 绝对路径。
- RUN 输出目录绝对路径。
- 汇总 `report.md` 绝对路径。
- 已通过门禁的单篇报告路径列表。
- DOI 到 PDF 绝对路径映射。
- DOI 到 Markdown 绝对路径映射。
- 失败条目列表及原因。
- 需人工处理条目列表及原因。
- 已跳过的 collection 内已有 DOI 列表。
- `{RUN}/pdf-download-rule-candidates.md` 路径；如果不存在，说明无候选规则。
- 报告语言。

如果调用方已知，也应一并提供这些运行元信息，用于填写汇总基本信息：

- RSS feed 标识或名称。
- 条目日期范围。
- 本次 RUN 的总条目数。
- 无 DOI 而被跳过的条目数；如果未知，写“未提供”。

## 汇总要求

使用 `references/report-template.md` 的结构生成报告。

汇总报告必须保留：

- 成功研究论文。
- 已跳过已入库 DOI。
- 失败或需人工处理条目。
- PDF 下载规则候选；没有时写“无”。

在“单篇论文摘要”中，Markdown 和 PDF 路径必须优先来自调用方传入的映射或
`process-items.json` 字段；只有字段为空或文件不可读时，才写“未发现文件”，并说明原因。

## 汇总原则

- 一份汇总报告可以包含 0 个、1 个或多个主题，按本次语料自然分组。
- 先综合主题，再列单篇论文；避免只把单篇摘要机械拼接。
- 一个主题至少由 2 篇 `studied` 论文支撑；只有 1 篇支撑时，放入“单篇值得关注的观察”，不要强行上升为主题。
- 每个主题都列出支撑 DOI；存在反例或冲突时，同时列出反例或冲突 DOI。
- 优先突出跨论文的共同问题、可复用方法和后续行动。
- 主题归纳时综合以下三项判断：
  - 与主题相关性：`高` / `中` / `低`
  - 证据充分性：`高` / `中` / `低`
  - 方法可信度：`高` / `中` / `低`
- 对低质量、证据不足或与主题弱相关的论文，应在汇总中降低权重并说明原因。
- 如果不同论文结论相反，不要硬合并成单一结论；单列“分歧与不确定性”，并说明可能原因，例如数据、样本、任务、指标或方法差异。
- 保留跳过、失败和需人工处理的条目，方便后续补跑。
- 样本较少时，用“本批次论文显示”“在本次语料中观察到”这类措辞，避免写成领域级普遍结论。

## 完成门禁

汇总任务的交付物是 RUN 目录下的汇总 `report.md`。

必须按以下顺序完成：

1. 写入汇总 `report.md`。
2. 验证文件存在且大小大于 0。
3. 验证报告包含所有 `studied` DOI。
4. 验证报告列出所有 `failed` 和 `needsManual` DOI 及原因。
5. 验证报告列出 `skippedAlreadyInCollection` 计数；如果有跳过条目，列出 DOI。
6. 验证报告的“主题归纳”对每个主题列出支撑 DOI；如果无可归纳主题，明确写“无可归纳主题”。
7. 验证报告包含“分歧与不确定性”小节。
8. 验证报告包含“PDF 下载规则候选”小节；没有候选时写“无”。
9. 验证通过后，最终回复只报告报告路径和验证结果。

未通过本门禁时，不得声称汇总完成。
